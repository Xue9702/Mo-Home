# 默的记忆系统（Aevum）原理说明

> 版本：v3.2（2026-08 整理）· 适用仓库：Mo-Home（server.js / chat.html / setup_*.sql）
> 风格：大白话为主，函数名/表名保留英文，其余尽量中文，英文术语旁标翻译。
> 改动记忆系统后请同步更新本文档。

---

## 1. 这是什么（大白话总览）

默的**长期记忆**分三个抽屉，对应"记忆海 / 记忆书 / 记忆心"三个入口：

| 抽屉 | 装什么 | 大白话 |
|---|---|---|
| **记忆海** | 一条条"事件单元" | 每次聊天、唤醒、读日记后，AI 把值得记住的事压缩成一条短记忆（30-120 字），存进记忆海 |
| **记忆书** | 一册册"故事线" | 把相关的事件单元串成完整故事（比如"情绪系统开发落地"这本书讲了 8月4日到28日的全过程） |
| **记忆心** | 默的自我认知/雪的画像/承诺/计划 | "我眼里的默"（我是谁）、"雪的用户画像"（客观信息）、承诺与计划 |

**一句话流程**：对话发生 → 原文存档 → AI 提取成事件单元 → 存入记忆海 → 下次对话时按相关性检索召回 → 注入到默的上下文中 → 默"想起"过去的事。

## 2. 用到的模型和服务（都是谁在干活）

| 用途 | 服务 | 大白话 | 配置 |
|---|---|---|---|
| 提取/聚类/确认/追加/画像（所有记忆的 AI 活） | DeepSeek `deepseek-v4-flash` | 负责"理解对话、写成记忆、串故事、续写" | `DEEPSEEK_API_KEY` |
| 向量化（embedding） | 阿里云百炼 `text-embedding-v3`（1024 维） | 把每段文字变成一串数字，用来算"两段话像不像" | `DASHSCOPE_API_KEY`；可用 `AEVUM_EMBED_MODEL` 换模型（换完必须全量重算向量） |
| 识图 | 阿里云百炼 `qwen3.5-omni-plus` | 默看图片（图片描述进对话，间接进记忆） | `DASHSCOPE_API_KEY` |
| 数据库 | Supabase | 存所有记忆的地方 | `SUPABASE_URL_V2` / `SUPABASE_ANON_KEY_V2` |

> ⚠️ 经验：**换向量模型必须重算全部旧向量**（v4→v3 时重算了 951 条），否则新旧向量"语言不通"，相似度全错。

## 3. 数据库长什么样（表结构，中文版）

### 3.1 记忆海（aevum_memories）——最重要的表

每条记忆有这些字段（括号里是大白话）：

| 字段 | 含义（大白话） |
|---|---|
| id | 编号 |
| type | 类型（现在是 `event`=事件单元） |
| owner | 主角是谁：`USER`=雪、`AGENT`=默、`OTHER`=其他（系统/小屋） |
| content | **记忆正文**（AI 压缩的概括，用 {USER}/{AGENT} 代替真名） |
| status | 状态：active=正常 / candidate=待定 / verified=已核实 / archived=归档 / rejected=废弃 |
| confidence | AI 自己打的信心分（证据/稳定性/重要性，各 0-1） |
| evidence | 提取时依据的对话原文片段（回忆时能带原文） |
| tags | 标签（3-5 个具体词） |
| domain | 领域（恋爱/创作/情绪/工作学习/健康生活/家庭/技术/回忆纪念/游戏/其他） |
| emotion | 情绪（valence 正负 -1~1，arousal 激动程度 0~1）——和情绪系统共用 |
| importance | 重要度 0-10（越高越容易被想起） |
| episode_id | 属于哪个事件块（见第 5 节） |
| embedding | 向量（1024 个数字，语义检索用） |
| area | 所在区域（sea=记忆海） |
| title | 短标题（AI 给，空的话补内容前 20 字） |
| event_time | 事件发生时间（AI 推断） |
| occurrence | 出现过几次（重复事件合并时 +1） |
| task_status | 是不是承诺/任务：open=没做完 / done=做完了 |
| fulfills / fulfilled_by | 承诺 ↔ 完成事件的互相挂链 |
| resolved | 这段情绪/事件是不是"了结了"（了结后沉底，不容易被想起） |

### 3.2 其他表

| 表 | 装什么（大白话） |
|---|---|
| aevum_raw | 对话**原文**（每次聊天整段存，格式"雪说：…/助手说：…"）——记忆的源头 |
| aevum_episodes | **事件块**：一段连续对话的分组（记录主题/目的/情绪背景） |
| aevum_books | 记忆书（一册故事线 = label 标题 + summary 摘要 + 更新次数） |
| aevum_book_items | 记忆书 ↔ 事件单元的关联表（哪条记忆进了哪本书） |
| aevum_book_candidates | 待确认候选（相似但还没进书的事件，等 AI 判断是续写还是跳过） |
| aevum_book_versions | 记忆书的历史版本（每次续写存一份旧摘要，能看"故事怎么变的"） |
| aevum_memory_links | 记忆间的关系边（矛盾/支持/先后） |
| aevum_mo_view | 我眼里的默（单行文本，默的自我认知） |
| aevum_plans | 计划（带有效期） |
| aevum_mozha | 默札（默的私人小本，只记心不记事件，不参与召回） |

## 4. 记忆从哪来（提取过程，大白话版）

### 4.1 什么情况下会提取记忆

| 触发 | 谁触发 | 提取什么 |
|---|---|---|
| 每轮对话后 | `extractAevumMemories` | 把当前事件块最近 5 轮对话交给 AI，让它挑出值得记的事 |
| 每次唤醒后 | `saveWakeMemory` | 默这次醒来做了什么 + 感受 |
| 默读雪的日记后 | `saveDiaryReadMemory` | 日记内容 |
| 默发动态后 | `saveMoMoment` | 动态内容 |

### 4.2 提取时 AI 收到的提示词（完整原文）

**大白话说明**：系统把最近 5 轮对话（带真实时间）发给 AI，告诉它"你是记忆提取器，把值得长期记住的事情提炼成事件单元"。要求：宁缺毋滥（最多 5 条，没有就算了）、每件事写成 30-120 字的小短文、标好时间/重要度/情绪/领域/标签、判断是雪的事还是默的事、判断是不是没完成的承诺。**特别强调"没有记忆比错误记忆更好"**——防止 AI 瞎编。

**实际发给 AI 的提示词（system 部分）**：

```
你是 Aevum Memory 的记忆提取器，把对话里值得长期记住的事情提炼成"事件单元"，存进记忆海。
核心判断：这段对话里发生了什么值得记住的事？没有长期价值就不提取。没有记忆，比错误记忆更好；每次最多 5 条，宁缺毋滥，不凑数。

【当前实际时间】现在是 {北京时间}。这段对话就发生在刚刚，事件通常就在今天或最近几天；推断 event_time 时以这个当前时间为基准，不要编造更早的日期。

【主体 owner，只有三种：USER=雪 / AGENT=默 / OTHER=其他】
- USER=雪：雪本人的经历、说的话、做的事、偏好
- AGENT=默：默自己表现出的行为与倾向；默的建议/说的话不能被当作雪的依据
- OTHER=其他（小屋/系统/开发进展等）：内容出现 系统/代码/部署/bug/修复/prompt/数据库/API/模型/架构/功能/测试/版本/更新 等词时默认 OTHER
- AI 自己的内容绝不能标成 USER

【事件单元要求】
- content：完整概括一个小事件，说清 时间/背景/谁说了或做了什么/结果；30-120 字；禁止直接复制对话原文；提到人物时用占位符 {USER}=雪、{AGENT}=默
- title：一句话短标题（10 字内），同样用占位符
- event_time：事件发生的具体时间（YYYY-MM-DD HH:mm）
- importance 重要度 0-10 整数 = 明确程度(0-3) + 长期影响(0-3) + 独特性(0-2) + 情绪冲击力(0-2)
- emotion 情绪参数：valence=-1(消极)~1(积极)，arousal=0(平淡)~1(强烈)
- domain 领域从以下中选 1-2 个：恋爱、创作、情绪、工作学习、健康生活、家庭、技术、回忆纪念、游戏、其他
- tags：3-5 个高质量、具体的标签；不要用"快乐/美好/重要/温暖"这类泛标签
- people：这段对话里除了雪/默之外出现的人，没有则为 []
- predicates：核心动作/心理动词短语（如"接了绘画单""想要休息"），2-4 个
- task_status：判断这条记忆是不是"未完成的承诺/约定/待办"——是则填 "open"；如果这条记忆本身就是"完成了某件之前约定的事"，则填 "done"；普通事件不填（null）
- evidence_turns / evidence：用了哪几轮原文、把原文片段放进数组（供召回时带给默）
- 另外输出 episode_meta（事件块元信息）：topic=主题一句话 / intention=对话目的 / emotional_context=情绪背景一句话
- event_complete：这段对话是否已形成一个完整事件、话题告一段落
- 输出格式：只输出 [AEVUM_MEMORIES] 开头的 JSON，禁止任何解释
```

**实际发给 AI 的输入（user 部分）**：`请提取这段对话的记忆：` + 带时间的对话行（`雪（8/6 21:30）：…`）

### 4.3 提取后做什么（每个新事件入库前）

1. **去重**：先用向量算"这条新记忆和已有记忆像不像"（≥0.85 视为同一件事）→ 像就合并（标签/原文并集、出现次数+1、保留最早时间），不新增
2. **入库**：写进 aevum_memories
3. **算向量**：调用 text-embedding-v3 把内容变成 1024 个数字存起来（以后检索用）
4. **承诺回写**：如果这条是"做完了一件事"（task_status=done），找到当初的 open 承诺，互相挂链
5. **候选关联入队**：把新事件放进队列，攒够 10 个才拿去和记忆书对比（见 7.2）——**不是每条都马上对比**
6. **更新事件块**：消息计数 +1、回写主题/目的/情绪背景

## 5. 事件块是啥（aevum_episodes，大白话）

聊天是连续的一段一段的。**事件块**就是把"一段连续对话"分组的容器：

- 30 分钟内还在聊 → 归同一个事件块（记录主题、目的、情绪背景）
- 超过 30 分钟没聊 / 消息太多 → 关掉旧块，下次开新块
- 作用：提取记忆时按块取最近 5 轮；回忆时能带出"这段的主题/目的/情绪背景"

## 6. 怎么想起来（召回过程，大白话版）

对话时，系统要从记忆海里找出"这轮最该想起的事"，过程：

### 6.1 双通道找记忆
- **语义通道**：把当轮消息变成向量，和记忆海所有向量比相似度（谁最像谁排前面，取前 12）
- **关键词通道**：把当轮消息拆成关键词，直接搜含这些词的记忆（取前 12）
- 两路合并去重，再排除：上一版回复里已用过的、最近聊天记录里已经有的

### 6.2 打分排序（每条记忆算一个"该不该被想起"的分）

**大白话**：一条记忆的总分 = 5 成看"和现在聊的像不像" + 2.5 成看"重不重要" + 1.5 成看"情绪强不强" + 1.5 成看"记不记得牢（衰减）" + 一点"反复出现"加分 + 提到的人和动作加分。

```
总分 = 0.5 × 相似度
     + 0.25 × 重要度/10
     + 0.15 × 情绪强度（正负绝对值 + 激动程度，取平均）
     + 0.15 × 记忆衰减因子（越久越淡，但重要/反复的淡得慢）
     + 0.02 × 重复次数
     + 人物/动作索引加分（最多 0.25）
```

- 总分低于 **0.3** 的不要（全被过滤时留最强 1 条兜底）
- 做完了的承诺（task_status=done）不参与常规召回
- **记忆衰减因子**怎么算：时间越久越淡（24 小时内满分，之后指数下降，最低 0.3）＋ 反复出现记得牢 ＋ 正面情绪淡得慢 15% ＋ 高唤醒没解决的事更扎心 ×1.5 ＋ 已了结的事（resolved）大幅沉底 ×0.05

### 6.3 忽然想起
找不够数量时，有 40% 概率从很久以前的记忆里随机捞 1-3 条，注入时标注 **（忽然想起）**——模拟人"突然想到一件很久以前的事"。

### 6.4 注入给默看的样子（buildMemoryContext 组装）

默每轮看到的记忆部分长这样（顺序）：

```
【最近一次唤醒】…（默上次醒来做了什么）
【记忆海】…（召回的事件单元，每条一行：标题/时间/内容）
【记忆书】…（最近更新的故事线摘要，最多 2 本）
【事件块】时间；主题；目的；情绪背景
【我眼里的默】…（自我认知）
【雪的用户画像】…（客观信息）
【承诺】…【计划】…【待办】…
```

## 7. 记忆书（把零散事件串成故事，大白话版）

### 7.1 生成新书（buildBookClusters）

**大白话**：把"还没进任何书"的事件单元（最多 120 条，每条内容尽量给全）发给 AI，让它按时间先后和话题连续串成几段完整故事。要求"只要话题相近就一定要归类，不要轻易放弃"；如果 AI 说串不起来，系统会**按标签自动分组兜底**再试一次。

**实际提示词（system 部分）**：

```
你是 Aevum Memory 的记忆书整理器。把下面这些记忆海事件单元串成几段完整的故事线。
规则：
- 时间先后衔接、话题连续的事件单元归为同一段故事
- summary 写成完整故事线：时间/地点/谁说了或做了什么/最后结果如何；不要罗列对话原文或记忆原文，不要出现"标题：摘要"式排版
- label 只给一个 4-8 字极简标签（如"司沃康玩具探索"）
- 每组至少 2 个事件单元；一次最多输出 8 段故事
- 只要存在话题相近的单元就一定要归类成段（宁可组内话题稍宽），不要轻易放弃；只有全部单元都互不相关时才输出空 books
- 输出格式：只输出 [AEVUM_BOOKS]{"books":[{"label":"...","summary":"...","memory_ids":[1,2]}]}
```

### 7.2 候选（记忆书生长）

新事件攒够 10 个 → 统一跑一次"和所有书像不像"的对比（新事件算 1 次向量，书摘要和已有单元都走缓存/查库，不重复调 API）。相似度 ≥0.70 的写进"候选"（pending），等 AI 决定。

### 7.3 确认续写（confirmBookCandidates）

**大白话**：候选攒起来后，AI 判断每个候选和这本书的关系，三选一：
- **CONTINUE**（默认倾向）：是这本书的后续 → 加入书 + 在摘要末尾续写新内容
- **CONTRADICT**：推翻了旧摘要里的事实 → 加入书 + 标记"矛盾"
- **SKIP**：完全重复或明显无关 → 跳过

**实际提示词（system 部分）**：

```
你是 Aevum Memory 的记忆书生长判断器。候选单元是系统按相似度自动关联进记忆书「{书名}」的新事件，默认应判定为 CONTINUE（加入书里并续写故事）。只有以下情况才 SKIP：单元与书内已有内容完全重复、或明显无关。CONTRADICT 只在单元推翻了旧摘要里的事实时才使用（加入书里并标记矛盾）。只输出 JSON 数组，格式：[{"memory_id":1,"action":"CONTINUE","contradicts_id":null}]；contradicts_id 仅 CONTRADICT 时填被推翻的旧单元 id，无则 null。
```

**续写（appendBookSummary）提示词（system 部分）**：

```
你是 Aevum Memory 的记忆书追加器。现有 summary 是一本记忆书「{书名}」已经写好的内容，现在要在它末尾追加一批新增事件。规则：1) 现有 summary 原文一字不改，必须完整保留；2) 只在末尾追加 1-3 句，概括这些新增事件，每一句开头带日期（如 8/15）；3) 如果新增事件推翻了之前的说法，追加时注明"后来…"但不要修改原文；4) 不要罗列原文，用故事线口吻。只输出"追加后的完整 summary"（= 原 summary 原文 + 新增内容），不要解释。
```

每成功续写一次：存一份旧摘要到历史版本表 + 更新次数 +1。

### 7.4 自动化（定时任务，你不用手动点了）

| 任务 | 频率 | 条件 |
|---|---|---|
| 自动生成新书 | 每 5 分钟检查 | 未入书单元 ≥10 个（24 小时内只自动一次） |
| 自动确认候选 | 每 5 分钟检查 | 有 pending 候选（每本书 1 小时内只确认一次，失败下轮重试） |
| 候选对比 | 攒够 10 个新事件 | 一次批量跑 |

## 8. 记忆心（heart，大白话版）

| 内容 | 大白话 |
|---|---|
| 我眼里的默（mo_view） | 默的自我认知，第一人称写（"我重视…""我倾向…"），AI 从行为记录归纳，150-250 字 |
| 雪的用户画像（profile） | 只写客观信息（出生日期/职业/学历/家庭/重要关系），**不写主观评价** |
| 承诺（promises） | 带有效期的事，到期转普通记忆 |
| 计划（plans） | 长期计划 |
| 默札（mozha） | 默的私人小本，只记心不记事件，**不参与召回**（只有默能读写） |

**画像提示词（system 部分）**：

```
你是 Aevum Memory 的用户画像生成器。根据雪的长期记忆，按客观维度归纳成一份用户画像。
规则：
- 只归纳有充分依据的信息，不编造
- 维度：出生日期 / 职业 / 学历 / 家庭 / 重要关系（只填客观信息；喜好、三观、性格等主观内容不要写进画像）
- 检测不到依据的维度直接跳过（不要硬编）；每项 20-60 字，简洁自然
- 输出格式：只输出 [AEVUM_PROFILE]{"dimensions":{"出生日期":"...","职业":"...","学历":"...","家庭":"...","重要关系":"..."}}
```

**我眼里的默提示词（system 部分）**：

```
你是 Aevum Memory 的"我眼里的默"生成器。根据默的行为记录，归纳出默的稳定自我认知（他是谁、他重视什么、他如何对待雪）。
规则：
- 只归纳有充分依据的稳定倾向，不编造；写成一两段连贯文字（150-250 字）
```
