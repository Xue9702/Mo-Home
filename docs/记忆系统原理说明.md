# 默的记忆系统（Aevum）原理说明

> 版本：v3.x（2026-08 整理）· 适用仓库：Mo-Home（server.js / chat.html / setup_*.sql）
> 本文档用于理解系统全貌、排查问题、规划改造。任何改动后请同步更新。

---

## 1. 系统定位与总览

Aevum 是"默"的长期记忆系统，三入口结构：

- **记忆海（sea）**：事件单元（从对话/唤醒/日记/动态提取的单条记忆），支持语义检索
- **记忆书（book）**：把相关事件单元串成的"故事线"（长摘要），供回忆时注入
- **记忆心（heart）**：我眼里的默（mo-view）、用户画像（profile）、承诺（promises）、计划（plans）、默札（mozha）

数据流全景：

```
对话/唤醒/读日记/发动态
   ↓ 原文存档（aevum_raw）
   ↓ 事件块归属（aevum_episodes，30 分钟窗口）
   ↓ LLM 提取（deepseek-v4-flash）→ 事件单元（aevum_memories）
       ├─ 去重合并（向量 ≥0.85 / 文本包含）
       ├─ 承诺回写（task_status open/done ↔ fulfills）
       ├─ 向量化（dashscope text-embedding-v3，1024 维）
       ├─ 候选关联队列（攒 10 个 → 对比记忆书）
       └─ 事件块元信息回写（topic/intention/emotional_context）
   ↓ 检索召回（对话时）
       ├─ 向量 + 关键词双通道 → 混合打分 → 0.3 阈值
       ├─ 忽然想起（40% 随机浮现旧记忆）
       ├─ 记忆书场景（故事线摘要 + 事件块元信息）
       └─ 记忆心（mo-view/画像/承诺/计划/待办）
   ↓ 注入 system prompt（buildMemoryContext → buildSystemPrompt）
```

## 3. 表结构（真实列，2026-08 查库）

### aevum_memories（记忆海，核心表）

| status | text | `active` / `candidate` / `verified` / `archived` / `rejected` |
| confidence | jsonb | {evidence, stability, importance} 各 0-1 |
| evidence | jsonb[] | 提取依据的对话原文片段（召回时可附带） |
| tags | jsonb[] | 3-5 个具体标签 |
| domain | jsonb[] | 恋爱/创作/情绪/工作学习/健康生活/家庭/技术/回忆纪念/游戏/其他 |
| emotion | jsonb | {valence: -1~1, arousal: 0~1}（情绪系统共享） |
| importance | int | 0-10 |
| episode_id | bigint | 所属事件块 |
| embedding | float[] | 1024 维向量（text-embedding-v3） |
| area | text | `sea`（记忆海） |
| title | text | 短标题（提取时 AI 生成，可为空→补内容前 20 字） |
| event_time | timestamptz | 事件发生时间（AI 推断） |
| occurrence | int | 出现次数（重复事件合并 +1） |
| task_status | text | `open`（未完成承诺）/ `done`（已完成）/ null |
| fulfills / fulfilled_by | int[] | 承诺 ↔ 完成事件的双向挂链 |
| resolved | bool | 情绪/事件是否已了结（衰减 ×0.05 沉底） |
| layers | jsonb[] | 层级归属（deep/daily/... 预留） |

## 4. 提取链路（怎么把对话变成记忆）

### 4.1 触发时机
| 来源 | 函数 | 输入 |
|---|---|---|
| 每轮对话后 | `extractAevumMemories` | 当前事件块最近 **5 轮**原文（getEpisodeRecentExchanges） |
| 每次唤醒后 | `saveWakeMemory` | 唤醒动作 + 体验总结 |
| 默读雪的日记后 | `saveDiaryReadMemory` | 日记内容 |
| 默发动态后 | `saveMoMoment` | 动态内容 |

### 4.2 提取调用（deepseek-v4-flash）
- 输入：带真实时间的对话行（`雪（8/6 21:30）：…`）
- 系统提示要求输出 `[AEVUM_MEMORIES]` 开头 JSON：
  - `episode_meta`：topic / intention / emotional_context（回写到事件块）
  - `event_complete`：话题是否告一段落（决定事件块关闭）
  - `memories[]`：title / content / event_time / owner / domain / emotion{valence,arousal} / importance / evidence_turns / evidence / tags / people / predicates / task_status
- 关键规则：宁缺毋滥、最多 5 条、owner 严格区分（AI 内容不能标 USER）、内容用占位符不用真名

### 4.3 入库前处理（每个新事件）
1. **去重**（aevumFindDuplicate）：先向量相似度 ≥0.85（RPC match_aevum_memories_scored），退回文本包含判断；命中则合并（mergeSeaDuplicate：tags/evidence 并集、occurrence+1、保留最早时间）
2. **写入** aevum_memories（area='sea'、status 依配置）
3. **向量化**（ensureAevumEmbedding）：text-embedding-v3 → 写 embedding 列
4. **承诺回写**（checkPromiseFulfillment）：若 task_status=done，找到源头 open 承诺双向挂链
5. **候选关联入队**（queueBookAssociation）：攒够 10 个统一跑 checkBookAssociation
6. **事件块计数**（appendToEpisode）+ 元信息回写（updateEpisodeMeta）

## 5. 事件块机制（aevum_episodes）

- **语义分段**：一段连续对话归为一个事件块（topic/目的/情绪背景）
- **30 分钟静默窗口**：超窗或消息 ≥ EPISODE_MAX_MESSAGES → 关旧开新（getOrOpenEpisode）
- **场景召回**（getEpisodeScene）：召回时注入"【记忆书】+【事件块】时间/主题/目的/情绪背景"（不再注入对话原文）

## 6. 召回链路（对话时怎么想起）

`recallAevumMemories(text, limit=5, excludeText, historyText)`

### 6.1 双通道召回
- **向量通道**：getEmbedding(query) → RPC match_aevum_memories_scored（top 12）
- **关键词通道**：取 2 字以上关键词 → content ilike 匹配（top 12）
- 合并去重；排除与上一版回复重合的、已在最近历史里的内容

### 6.2 混合打分（v3.1）
```
score = 0.5 × 向量相似度
      + 0.25 × (importance/10)
      + 0.15 × 情绪强度（(|valence|+arousal)/2）
      + 0.15 × min(1, 记忆衰减因子)
      + 0.02 × min(occurrence-1, 4)          # 频率
      + 人物/谓词索引加分（≤0.25）
```
- 0.3 阈值兜底（全被过滤时保留最强 1 条）
- 已完成承诺（task_status=done/cancelled）不参与常规召回
- **记忆衰减因子**（memoryDecayFactor）：时间幂律（24h 内鲜活 → 0.9×e^(-0.22×天数) 保底 0.3）× occurrence^0.3 × FAB（正面 ×1.15）× 高唤醒未解决 ×1.5 × resolved 沉底 ×0.05

### 6.3 忽然想起
召回结果 < 请求数时，40% 概率从 3 天前的旧记忆随机浮现 1-3 条，注入时标记 **（忽然想起）**

### 6.4 注入格式（buildMemoryContext 组装）
```
【最近一次唤醒】…（最近唤醒的动作+总结）
【记忆海】…（召回的事件单元行）
【记忆书】…（最近更新的故事线摘要，最多 2 本）
【事件块】时间；主题；目的；情绪背景
【我眼里的默】…（mo-view）
【雪的用户画像】…（profile）
【承诺】…（进行中的承诺）
【计划】…【待办】…
```

## 7. 记忆书系统

### 7.1 生成（buildBookClusters）
- 输入：**未入任何书**的事件单元（area='sea' 且不在 book_items，最多 120 条，内容给全至 500 字/条）
- LLM（deepseek-v4-flash）聚类：按时间/话题串成故事，输出 `[AEVUM_BOOKS]{books:[{label, summary, memory_ids}]}`
- 兜底：AI 空结果时按共享标签贪心分组重新生成
- 产物：aevum_books + aevum_book_items（事件单元入册）

### 7.2 候选关联（checkBookAssociation，队列批量）
- 新事件攒够 **10 个** → 对新事件算 1 次向量，与所有书（摘要 + 最多 20 个已有单元）对比
- 相似度 ≥0.70 → 写 aevum_book_candidates（status=pending）
- 书摘要向量内存缓存（10 分钟 TTL）；单元向量**查库优先**（零 API）

### 7.3 生长确认（confirmBookCandidates）
- 触发：手动"生成故事"按钮 / 自动确认定时器
- LLM 三选一：**CONTINUE**（加入并续写，默认倾向）/ CONTRADICT（加入 + 标记矛盾边）/ SKIP（跳过）
- 续写：appendBookSummary（保留原文 + 末尾追加带日期的新内容，上限 2500 字）
- 每成功续写一次：版本存档（aevum_book_versions）+ updated_count +1

### 7.4 自动化定时器
| 任务 | 周期 | 条件/防抖 |
|---|---|---|
| 自动串联（生成新书） | 5 分钟检查 | 未入书单元 ≥10，24h 防抖 |
| 自动确认（生长） | 5 分钟检查 | 有 pending 候选；每书 1h 防抖（失败不防抖可重试） |
| 候选关联（对比书） | 队列攒够 10 个 | 内存队列（重启丢失） |

## 8. 记忆心（heart）

- **我眼里的默**（aevum_mo_view）：单行文本，默的自我认知/性格（LLM 生成，可手动改）
- **用户画像**（profile）：按维度归纳（出生日期/职业/学历/家庭/重要关系），只写客观信息
- **承诺**（promises）：带有效期，到期转普通记忆
- **计划**（plans）：长期计划
- **默札**（mozha）：默的私人小本，只记心不记事件，不参与召回

## 9. 已知问题与设计取舍（排查记录）

### 已修复
1. ~~候选关联实时全量对比~~（每事件 700+ 次 embedding）→ 队列攒 10 个批量，单元向量查库优先（本次）
2. ~~getUnitEmbedding 每次现算~~ → 查库优先 + 缓存 TTL
3. ~~appendBookSummary 500 字截断~~（长摘要追加内容丢失）→ 2500
4. ~~候选确认全 SKIP~~（AI 判定偏保守）→ 默认倾向 CONTINUE
5. ~~v4 额度耗尽~~ → 换 text-embedding-v3 + 全量重算（951 条）
6. ~~空标题~~（92% 无标题）→ setup_fix_titles.sql 补前 20 字

### 观察到的其他点（未处理，视需要再动）
- **aevum_memory_links 空表**：contradicts 关系边只在确认 CONTRADICT 时写入，从未触发过（存量无）
- **aevum_topics 空表**：旧主题已迁记忆书，新事件块 topic_id 为 null（记忆书场景只能靠最近更新命中）
- **aevum_plans 空表**：功能存在但未用
- **extractAevumMemories 每次对话调 LLM**（提取 + 情绪评分两条独立 LLM 调用）：成本可控（flash 模型），但可考虑合并
- **aevumFindDuplicate 每次新事件 1 次向量**：必要（新内容必须算）
- **recallAevumMemories 每次对话 1 次 query 向量**：必要
- **内存队列/防抖重启丢失**：自动串联/确认的防抖和候选队列都是内存态，重启后重新计时（可接受）
- **情绪与记忆共享 emotion 字段**：情绪系统给记忆打的 valence/arousal 会参与召回打分（emoIntensity 项）——设计如此，勿删

## 10. 排查速查

| 现象 | 看哪里 |
|---|---|
| 记忆没提取 | Render 日志 `Aevum 自动提取失败` / `Aevum 原文存档失败` |
| 提取了没进书 | 候选关联：日志 `📌 批量记忆书关联检查` |
| 候选全 SKIP | confirmBookCandidates 的 AI 判定（默认续写已修） |
| 召回不准 | recallAevumMemories 打分日志；确认 embedding 模型一致 |
| 额度异常 | 检查 embedding 调用量（查库优先已修） |
| 记忆书不更新 | confirm 后看 updated_count/版本表；appendBookSummary 失败日志 |
