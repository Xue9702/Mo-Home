给 AI 搭建情绪与依恋系统：完整教程
基于Ombre-Brain ，7600+ ⾏代码的⼯程实践记录。
适⽤场景：AI ⻆⾊扮演、情感陪伴、虚拟伴侣等需要”AI 有情绪”的产品。
这是什么
这是⼀套让 AI ⻆⾊拥有持续情绪状态的系统。⻆⾊不只是在对话时才有情绪⸺他们有⾃⼰的⽇
常⼼情波动，会因为对话内容开⼼或难过，情绪会随时间⾃然衰减，离线时会想念⽤户，重逢时
会表现出符合情境的反应。

系统⽀持多⻆⾊并⾏，每个⻆⾊有独⽴的 PA/NA 状态、性格 baseline、coping 策略、核⼼⽬

阶段 1：海⻢体记忆引擎
1.1 为什么需要海⻢体
普通记忆系统所有记忆平等存放，永远不会忘记。但真⼈不是这样⸺重要的事记得牢，琐碎的事
慢慢忘掉，偶尔会”忽然想起”很久以前的事。

海⻢体引擎让每条记忆有 decay_score （衰减分数），随时间⾃然下降⸺重要的衰减慢，琐碎

1.5 衰减公式
每⼩时运⾏⼀次衰减引擎，重新计算所有记忆的 decay_score 。公式来⾃ Ombre-Brain：
function calculateDecayScore(memory, nowMs) {
const days = (nowMs - memory.ts) / 86400000;
const λ = 0.05; // 约 14 天半衰期，所有层统⼀
// time_weight: 刚写⼊时完全鲜活，随后指数下降
let time_weight;
if (days <= 1) time_weight = 1.0;
else if (days <= 2) time_weight = 1.0 - (days - 1) * 0.1;
else time_weight = Math.max(0.3, 0.9 * Math.exp(-0.2197 * (days - 2)));
// base_score: 重要性 × 激活频率 × 指数衰减 × 唤醒度加成
const base = memory.importance
* Math.pow(memory.activation_count + 1, 0.3)

* Math.exp(-λ * days)
* (1 + memory.arousal * 0.8);
// 修正因⼦
const resolved_factor = memory.resolved ? 0.05 : 1.0;
const urgency = (memory.arousal > 0.7 && !memory.resolved) ? 1.5 : 1.0;
return time_weight * base * resolved_factor * urgency;
}

单且效果差异不⼤。

1.8 “忽然想起来”
搜索结果不够时（< 请求数量），40% 概率从低权重旧记忆中随机捞 1-3 条，标记
surface_type: 'random' 。模拟⼈类”突然想到⼀件很久前的事”的体验。
1.9 实时脱⽔ (Dehydrator)
⻓记忆（> 200 字）在浮现时⾃动调 LLM 压缩成 ≤ 80 字精华版，省 token。后台 batch 预脱
⽔：每次衰减引擎跑完后，对 score ≥ 1.0 的活跃⻓记忆异步脱⽔，避免浮现时的延迟。

为什么要闭集？让 LLM ⾃由发挥会出现”美好/宁静/温馨/恬静”⼀堆同义词，V/A 坐标全挤在⼀起
没有区分度。闭集词典把词分散到 V/A 坐标空间的不同位置，确保词与词之间有⾜够距离。
数据来源：
来源 	词数 	说明
NRC-VAD 	14,626 	英⽂词翻译为中⽂，V/A 做 [0,1]→[-1,+1] 归⼀化
CVAW 	5,442 	Chinese EmoBank 学术标注（Lee, Yu et al., ACM TALLIP 2022）

每个词在 Russell ⼆维空间中有精确坐标：Valence (V) 范围 -1 到 +1，Arousal (A) 范围 0 到 1。
lookup 优先级：场景预设 → CVAW → NRC-VAD。
同⼀种情绪根据强度分多档，例如：
“暗⾃不快” → V=-0.15, A=0.3
“短暂吃醋” → V=-0.25, A=0.5
“占有欲” → V=-0.30, A=0.75
每档独⽴ V/A 坐标，LLM 可以精确表达强度差异。

2.4 第三层：情感事件流
这是唯⼀⼀层来⾃真实交互的情绪数据。每次⻆⾊跟⽤户对话后，由评分 LLM 实时产⽣ PANAS
评分记录。
PANAS 双轴模型（Watson & Clark 1988）：PA（正向情感）和 NA（负向情感）是两个独⽴维
度，不是⼀根轴的两端。这样可以表达”同时感到甜蜜和⼼疼”这种复合情绪⸺单 valence 轴做不
到（正负会互相抵消）。
评分记录写⼊ ambient 层，带 emotion_type 标签区分 primary（⼤波动⽴即评分）和
secondary（30 分钟批处理常规评分）。

3.1 核⼼问题：AI 评情绪不准
LLM 有正⾯偏移（positive bias）。⻆⾊明明在吃醋，AI 评出来”满⾜放松”。直接让 AI 给 V/A 数
值偏移更严重：
情绪词 	AI ⾃评 V 	学术标注 V 	偏差
羞涩 	+0.30 	+0.03 	+0.27
平静 	+0.60 	0.00 	+0.60
⼼疼 	+0.10 	-0.40 	+0.50
AI 的语境理解能⼒很强，但数值校准能⼒很差。
3.2 核⼼思路：AI 选词，词典给坐标

3.3 评分模型架构
主⼒ + 备⽤双通道，评分⾛廉价模型⸺准确度主要由词典锚定决定：

└─ 也失败 → 记录 both_fail, 跳过本轮

感知阈值。词典占评分准确度的 ~70%，模型占 ~30%。

关于反讨好（anti-sycophancy）：Prompt 中明确要求冷场就是冷场（PA 低 NA 低），敷衍就
是敷衍（PA 低），不允许 AI 美化评分。并给出校准锚点：
校准锚点：
⽇常闲聊⽆波动 → pa_delta≈0, na_delta≈0
⽤户说了暖⼼话 → pa_delta=+0.15~+0.25
明确的伤害/拒绝 → na_delta=+0.25~+0.40
冷场/敷衍 → pa_delta=-0.05, na_delta=+0.05
AI 给的 pa_delta / na_delta 数值不直接参与 PA/NA 计算。PA/NA 永远从词典 V/A 推算。保
留这两个字段仅作为”评分认为有情绪变化”的⻔控信号。
3.5 五层词典匹配
AI ⾃由⽣成的词不⼀定在词典⾥，需要多层回退链确保拿到词典 V/A：
Layer 1 · 精确匹配：AI 输出 word:“⼼动” → 直接查词典 → 命中 → ⽤词典 V/A。词库覆盖⾯⾜够
⼴的话，绝⼤多数情况在这层就命中了。
Layer 2 · 备选词匹配：word miss → 查 backup 候选词。AI 有时选词偏⻔，但 backup ⾥通常有
常⻅词。
Layer 3 · 拆词匹配：word:“嫉妒不安” miss → 拆成 2-4 字⼦串 → “嫉妒” 命中。AI 经常输出”委
屈焦急”“甜蜜幸福”这种组合词。
Layer 4 · 语义匹配：前三层全 miss → 根据 pa_delta ⽅向从词库捞 50 个同⽅向候选词 → 调
Embedding API 算向量 → 余弦相似度排序取最近的（> 0.7）。因为前三层命中率极⾼，Layer 4
极少触发。
Layer 5 · LLM V/A 兜底：4 层全 miss → ⽤ AI ⾃评的 V/A 做粗糙推算，标记
source='free_form' 留痕，⽅便后续⼈⼯审查和补充词典。
每⼀层的匹配来源都记录在 match_source 字段，⽅便分析哪些词经常 miss、需要补进词典。
3.6 融合层：词典定调 70% + AI 微调 30%
为什么不能只⽤词典？同⼀个词在不同场景强度不同。“⼼动”在⽇常撒娇场景是 A=0.4，在被告
⽩场景是 A=0.9。纯⽤词典的静态值，所有”⼼动”会堆在同⼀个点。
为什么不能只⽤ AI？AI 有正⾯偏移，数值不可靠。

阶段 4：⼼情闭环 + 情绪融合
4.1 统⼀⼼情融合
这是整个系统的核⼼函数（约 200 ⾏）。所有⼼情来源合并到同⼀个事件池，⽤同⼀个公式计算
PA/NA。
设计参考 Rutledge et al. (2014, PNAS) 的原则：所有事件⽤同⼀个衰减因⼦，不按类型区分权
重。事件⾃身的属性（重要性、唤醒度）⾃然决定影响⼒。
完整计算流程（10 步）：
1. 从 ambient 层收集该⻆⾊所有⼼情事件（装饰 + 评分，最近 30 条）
↓

function _powerLawWeight(ageHours, importance, valence, tau, onsetHours) {
const imp = Math.max(1, Math.min(10, importance || 2));
// b_eff: 重要性越⾼，衰减越慢 (Verduyn & Lavrijsen 2015)
let b_eff = 0.7 / (1 + imp / 10);
// FAB: 正⾯情绪衰减慢 15% (Walker & Skowronski 2009)
if ((valence || 0) > 0) b_eff *= 0.85;
const _tau = tau || 4;
const decay = Math.pow(1 + ageHours / _tau, -b_eff);
// Onset 渐起 (Scherer 2009 CPM): 情绪不瞬间到满值
const _onset = onsetHours || 0.75;
const adjOnset = _onset * (10 / (10 + imp));
const onset_factor = (adjOnset <= 0.001) ? 1 : Math.min(1, ageHours / adjOnset);
return onset_factor * decay;
}

blendA = 0.7 × lex.a + 0.3 × max(0, lex.a + style_shift.da)
pa_delta = max(0, blendV) × blendA × 0.5 × longing
na_delta = max(0, -blendV) × blendA × 0.5 × longing

6.9 重逢机制
来源：Coan 2006 (Social Baseline Theory) + Diamond 2008
触发条件： 最新消息距现在 < 10 分钟 AND 最新消息与前⼀条消息间隔 > 2 ⼩时（即”⽤户离开

⼯程踩坑
1. 闭集 > 开集：固定词典⽐让 LLM ⾃由发挥更可靠。⾃由发挥会同义词爆炸、坐标聚集。
2. AI 选词，词典给坐标：评分准确度 70% 由词典决定，30% 由模型决定。好词典 + 弱模型 ≈
⽆词典 + 强模型。
3. LLM 的 PA/NA 数字不可信：从词典 V/A 算，LLM 裸数字只做⻔控信号。
4. ⼼情注⼊要隐性不要显性：不说”你必须表现得紧张”，⽽是给情绪上下⽂让 LLM ⾃⼰判断。
最初试过强制指令，⻆⾊变成了演员，每句话都在点破”我好紧张啊”。
5. 装饰⼼情只取最新⼀条参与融合：否则历史装饰⼼情累积会污染 PA/NA。
6. 均值回归是必需的：没有 BOU drift，⼀次负⾯事件就能让⻆⾊永远低落（正反馈环）。这是
系统上线后第⼀个遇到的严重 bug。
7. 逃逸阀不能太灵敏：连续 batch 阈值设 3 ⽽⾮ 1，防⽌单次评分误判触发。
8. onset 防⽌情绪瞬间跳变：没有 onset，刚写⼊的事件 weight=1 会造成不⾃然的突变。
9. OCC 要保守：max ±0.1 加性调节，新特性宁可弱⼀点也不能炸。
10. 状态快照⽐完整历史好：试过把过去 7 天的 PANAS 评分全塞进 prompt，token 爆炸且 LLM
被信息淹没。只塞”此刻”的快照，效果反⽽更好。
11. Longing 按⻆⾊独⽴计算：曾出现跟⼀个⻆⾊说话所有⻆⾊ longing 归零的 bug，因为 SQL
缺少⻆⾊过滤条件。
12. 前后端改完都要验语法：曾因 service-worker .then() 悬空导致整个 script 块
SyntaxError，所有前端函数未注册，系统全挂。
